# Campaign completion and mission-list controls (build 81)

Each registered Player ID has its own persisted completed-mission set. A successful campaign outcome marks that mission immediately, before the score screen or next-mission transition. Repeating the same outcome does not write duplicate progress. Defeats, custom games, multiplayer, cinematics and replay viewing do not earn campaign marks. Force Victory counts as a campaign win, consistently with its existing effect on mission progression.

New campaign saves carry the immutable identity of the Player ID that began the campaign. Loading that save selects its original still-registered Player ID, so wins, restarts and campaign continuation remain with the same owner. Older saves can use their existing `profile` name while that original ID still exists. A deleted ID cannot be credited by old saves; deleting and recreating the same display name creates a new identity and an empty completion set. Other IDs are unaffected. The registry has no rename operation; entering a case-insensitive match selects the existing ID as before.

Previous versions did not record campaign completions, so this update starts recording new wins. It does not guess completion from installed maps, unlocked missions or the last selected mission. Normal save slots and game-state loading are unchanged.

The classic bitmap fonts do not include a Unicode checkmark. Completed rows use a small green check inside a green outlined circle. Both the original mission-history dialog and fallback list display it. Mission IDs, not translated titles, identify completion, so UI language changes preserve the marks.

The original mission-history dialog reserves a 36-pixel scrollbar rail (previously 20). Its original arrow artwork and circular grip are scaled together; arrow hit areas are 36 by 32 logical pixels. The thumb can be dragged without jumping when grabbed off-center, track taps jump to the chosen position, and arrows step one mission. Text stays in its own clipped row and cannot overlap the rail. OK and Cancel are 164 by 34 pixels instead of 123 by 29. The old narrow outlines embedded in `phist.pcx` are covered before these wider controls are drawn.

`python3 tests/run_campaign_progress81.py CORE_DIR --starcraft /path/to/StarCraft.mpq` executes the production outcome hook, progress store, mission-list layout, drawing and scrollbar handlers with host shims. It checks separate IDs, persistence, repeat outcomes, save ownership, ID deletion/recreation, excluded game modes, original font loading, hit geometry and drag reachability. It renders the original dialog with caller-owned artwork into `build-native/campaign81/mission-history.png`. This is a host render and interaction test, not a physical Android-device test. Original assets are not bundled.
